# Path to 066 MAP: native source, replica operator, local CPU

User asked for the best path to a best fit, local or CANFAR GPU. No new DEC.

## Decision (closed ADRs)

1. **Source visibilities:** local `/Users/thbrown/kilogas/DR1/visibilities/KILOGAS066.npz`. CANFAR `.../KILOGAS066.npz` is the same object (`Content-Length` 997305244). It is **native** 43240×1920, not the 881×125 replica. Do not fit 1920 native channels as the MAP product (DEC-066-VIS: full-res is post-MAP).
2. **Fit operator (replica 5 km/s recipe):** trim to the 30 km/s Ico cube velocity axis (8034–8536 km/s) plus 3 native guards; Hann `[0.25,0.5,0.25]` on that native axis; software bin **N=4** (weighted mean vis, sum weights); time 30 s and uv 10 m. YAML `obs_freq_range` [224.148, 224.506] GHz is **not** the line window (it clips the receding side). `spectral_trim_from_imaging_cube: true` is the replica intent.
3. **Hardware:** MAP on this M1 with jax-finufft. After aggregation, vis count is replica-scale; 066-5 was 210 ms on *unbinned* 56×43240. GPU/CANFAR is not the 066-8 path. Escalate to CANFAR only if one aggregated likelihood eval exceeds ~0.5 s (DEC-066-GRID).
4. **Native line-free preview:** `⟨w|V|²⟩≈2.59`, `s≈0.77` (sanity 0.3–1.5). Remeasure `s` on the **fit** array (DEC-066-WEIGHT). Forensic 0.826 was a different aggregation.

## Rejected

- Fitting native 1920×43240 (slow; Δχ² not comparable).
- YAML bin-8 as the 066 product (replica was bin-4).
- CANFAR GPU for MAP (wrong job class; no speed need once aggregated).
- Fetching a phantom aggregated npz from CANFAR (it is the native file).

## Residual risks

1. Re-aggregation may not reproduce 881×125 exactly; Δχ² vs the old forensic replica may differ. Record `(n_row, n_chan, Δv, N)` after aggregation.
2. Cube velocity is `VOPT`; visibilities use radio vs rest CO. Align the trim in the same convention as `freq_to_velocity_kms`.
